Fix silent-failure bugs blocking farmer launch

Rainfall band never reached the crop scorer. The band was read through two
chained lookups whose key types did not match (inner dict returns int,
irr_levels is keyed by str), so rain_val was always 1 for every district in
India. Every rainfall band scored alike, and because effective_water was
max(irr_val, 1), a farmer answering "rainfed, no irrigation" was scored as
though they had Medium irrigation -- rice returned "water needs met" for every
irrigation/rainfall combination in the country. Rainfall now supplements stated
irrigation by at most one level, and only for kharif and year-round crops.

Shipped .env placeholders were treated as configured keys. A placeholder is a
non-empty string, so os.getenv truthiness accepted it: the app spent a round
trip per request to be told 401, never reached the keyless provider, and
skipped the deterministic path. The guard that data_gov_mandi_client already
had is now advisory/services/api_keys.py and every key read uses it. Matching
is anchored rather than substring-based, since a random provider key can
contain "test" by chance.

Seed prices deleted. Real Agmarknet rows from 12-06-2026 sat behind a docstring
claiming they were a day old; they were 88 days old, and both accessors were
already unreachable.

CSP enforced, Permissions-Policy added. No external script, style or font host
remains in the frontend, so the CDN allowlist that forced Report-Only is gone.
unsafe-eval dropped; unsafe-inline stays until the inline handlers are
refactored. CSP_REPORT_ONLY=true reverts without a code change.

Farmer-facing controls now translate. The bottom navigation, the whole
crop-advisory form and the mandi controls were hardcoded Hindi and never
reached t(). 22 keys wired, 14 languages, verified 0 unresolved and 0
Devanagari leaking into another script.

Un-ignore the bundled Agmarknet reference; a bare data/ rule kept it out of the
repo and CI failed on a file that existed only locally.

297 tests pass (was 280, 2 failing).
